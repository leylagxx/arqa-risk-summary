# CLAUDE.md — правила работы агента в этом репозитории

## Контекст
Риск-сводка кредитного портфеля: PostgreSQL 16 (схемы `raw`, `reporting`) → YAML-семантика → Vega-Lite.
Принцип «конфиг вместо кода»: новый отчёт — это вьюха `reporting.v_*` и спека, а не новый код.

## Определения — не трактовать, не «улучшать»
- Портфель: Σ principal_outstanding × курс **на дату среза** (не на конец месяца, не средний), без `written_off = 1`.
- KZT в `fx.csv` отсутствует — курс = 1. К курсам только `LEFT JOIN`, после — проверка на NULL.
- PAR30/PAR90: `dpd > 30` / `dpd > 90` — строго больше.
- NPL: `dpd > 90 OR restructured = 1`.
- Провизии: NPL → 50%, иначе `dpd > 30` → 10%, иначе 1%. Порядок условий важен: NPL первым.
- Концентрация: по `group_id`, не по `borrower_id`.
Если определение кажется неполным — спроси, а не додумывай.

## Правила для SQL
- `raw` — только загрузка, без трансформаций и без ограничений: грязь должна быть видна.
- Все вьюхи — `CREATE OR REPLACE VIEW`. Скрипты идемпотентны, повторный `./run.sh` ничего не ломает.
- Дубли: убирать только полные дубли строк (`DISTINCT` по всей строке). Расходящиеся дубли по ключу —
  ошибка, проверка должна падать. Не использовать `DISTINCT ON` / `row_number() = 1` для «выбора любой».
- Любой джойн проверять на размножение строк: число строк до и после.
- Деньги — `numeric`, без `float`. Округлять только при отображении.
- Суммовые меры — аддитивные колонки в витрине (`par30_kzt` и т. п.); доли считаются как отношение сумм,
  никогда как `avg` от флага.

## Проверка результата — обязательно
- После любых изменений: `./run.sh` (включает `sql/03_checks.sql`, `scripts/verify.py`, `scripts/check_semantic.py`).
- Новая метрика = новая проверка в `03_checks.sql` и пересчёт в `verify.py` другим способом.
- Если цифра расходится — найти причину и описать её. **Никогда не подгонять** запрос под ожидаемое число
  и не ослаблять допуск проверки, чтобы она прошла.
- Аномалии данных не исправлять молча: выводить в `reporting.v_data_quality` и README.

## Дашборд
- Спеки Vega-Lite — `dashboard/specs/*.json`, данные — `dashboard/data/*.json` (выгружает `run.sh`).
- Не хардкодить даты и границы осей в спеках — выводить из данных.
- На одной оси — только величины с одним знаменателем (доли портфеля отдельно от покрытия NPL).
- После изменений — открыть страницу и посмотреть глазами (скриншот), а не только проверить JSON.
